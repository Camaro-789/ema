# Memoria del proyecto — arreglos y cómo verificar

> Este archivo es la **memoria** del proyecto: qué se rompió, por qué, cómo se
> arregló y qué prueba lo cubre. **Antes de tocar código, léelo**; y cada vez que
> se arregle algo nuevo, añade una fila aquí para no volver a caer en lo mismo.

## Cómo comprobar que TODO quedó funcionando (un solo comando)

```powershell
cd d:\Desktop\VS\ema
powershell -ExecutionPolicy Bypass -File .\verificar_todo.ps1
```

Hace dos cosas:
1. **Arranque**: importa la app (crea las tablas que falten) y avisa si algo falla.
2. **Suite completa**: corre las 12 pruebas (backend + frontend) y resume OK/fallos por prueba.

Si todo está en verde, el servidor arranca sano.

## Reglas para no volver a romperlo

1. **No renombrar** los `id`/`data-tooltip` que ya usan las pruebas (sobre todo en
   la barra inferior del diagrama y el modal de Propiedades).
2. Si una plantilla guarda un valor con texto extra (`"1x8 (10.7 dB)"`), **parsear
   con el parser compartido**, nunca con `split()` + `int()`.
3. Antes de dar algo por terminado: correr `verificar_todo.ps1`. Si algo queda en
   rojo, la memoria y la prueba deben actualizarse en el mismo cambio.
4. Las tablas nuevas se crean solas al arrancar (`Base.metadata.create_all`), así que
   **nunca** hay que borrar la base de datos para actualizar el sistema.
